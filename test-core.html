3. Annotate an existing entity

Prefills through Entity#assertionsForEditing() — the only door a form may prefill through, because .assertions returns whatever strategy the Entity happens to be on and a display document has no provenance. On save, a field that arrived with a source.citationSource is updated in place; one without is a new create. That is the create-vs-update trigger.

Note what saving does NOT do: an Entity has no way to know a write happened, so this page calls resolve({ fresh: true }) itself before re-reading. Skip that and the next save sees no citationSource and POSTs a duplicate assertion — the silent corruption antlers#1 describes. PR 3 moves that responsibility into deer-form.

    6. Delete

    rerum.delete() — exported under the name the back end uses. Pass the whole document when you have it: deleting an Annotation changes its target's /expanded merge, and the target can only be invalidated from a document that still names it. A tombstone does not. Watch the request log for the cache: reload that follows.

    Expect a surprise when you delete an Annotation that has been UPDATED: RERUM heals the version chain, so the version it superseded becomes live again and the property comes back with its older value rather than disappearing. Both read paths show what is live, which is correct — delete the whole chain if you meant to remove the assertion.
